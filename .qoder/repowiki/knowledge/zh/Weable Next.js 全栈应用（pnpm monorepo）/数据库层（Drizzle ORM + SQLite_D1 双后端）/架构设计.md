模块由三个文件构成清晰的职责分层：`schema.ts` 使用 `drizzle-orm/sqlite-core` 以声明式方式定义 `users`、`channels`、`images` 三张表及其 `relations()` 双向关联（含自引用 parent/children），并通过 `uuidv7` + `bs58` 生成 Base58 短 ID 作为所有主键的 `$defaultFn`；`index.ts` 暴露单一工厂函数 `getDb()`，优先通过 `@opennextjs/cloudflare` 的 `getCloudflareContext()` 探测并获取 D1 binding 构建 Drizzle 实例，若不在 Cloudflare 上下文则回退到基于 `better-sqlite3` 的本地 SQLite 文件（路径由 `DB_PATH` 环境变量控制，默认 `./.data/weable.db`，首次访问时自动创建目录），并以模块级变量缓存两个后端实例；`migrate.ts` 是独立的 CLI 入口，直接通过 `drizzle-orm/better-sqlite3/migrator` 对 `./migrations` 目录执行迁移，不依赖运行时 db 实例。依赖方向单向：`index.ts` → `schema.ts`，`migrate.ts` 仅依赖 Drizzle 迁移器与 Node fs/path。迁移元数据由 `migrations/meta/_journal.json` 维护，SQL 文件按序号命名并使用 `--> statement-breakpoint` 分隔多条语句。
