该目录是 speckit 工具链在项目根下的运行时配置中心，采用「声明式清单 + 可插拔扩展」结构：
- 顶层清单文件定义全局状态：`integration.json` 记录当前/默认 AI 集成（claude/qodercli/kilocode/speckit）及版本；`extensions.yml` 列出已安装扩展（assess、bug）并启用 `auto_execute_hooks`；`feature.json` 指向当前活跃特性目录；`init-options.json` 保存初始化选项。
- `templates/` 提供 spec/plan/tasks/checklist/constitution 等 Markdown 模板，由 speckit 在生成规范时渲染。
- `scripts/bash` 与 `scripts/python` 成对实现同一套生命周期操作（check_prerequisites、create_new_feature、setup_plan、setup_tasks），通过 `speckit.manifest.json` 中的 SHA256 校验确保完整性。
- `workflows/workflow-registry.json` 注册内置 workflow（如 Full SDD Cycle），对应 YAML 定义位于 `workflows/speckit/workflow.yml`。
- `extensions/` 以子目录形式承载扩展，每个扩展含 `extension.yml` 元数据与 `commands/*.md` 命令描述，按 schema_version 1.0 暴露 `speckit.assess.*` 系列命令。
- `integrations/` 中每个 AI 集成提供 `*.manifest.json` 描述其调用约定（script、invoke_separator）。
- `memory/.constitution-template.json` 与 `bugs/<slug>/assessment.md|fix.md` 分别用于持久化项目宪法与缺陷跟踪。
依赖方向单向：CLI → 清单解析 → 模板/脚本/扩展命令 → 产物写入 specs/ 等业务目录，不反向依赖业务代码。
