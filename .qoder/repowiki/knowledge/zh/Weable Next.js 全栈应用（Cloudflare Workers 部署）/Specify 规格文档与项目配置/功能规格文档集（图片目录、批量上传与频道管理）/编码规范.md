- 每个功能规格使用三位数字前缀加英文语义名称的子目录命名（如 001-image-directory-tree），并在 spec.md 头部标注功能分支、创建日期与状态。
- 规格文档统一包含 User Scenarios & Testing、Requirements、Success Criteria、Assumptions 四个必选章节，需求条目以 FR-XXX 编号，成功标准以 SC-XXX 编号。
- 接口契约文档存放在 contracts/ 目录下，文件名采用 HTTP 方法+资源名的形式（如 post-upload.md、patch-images-batch.md），描述请求路径、参数与响应格式。
- 用户故事采用 Given/When/Then 场景化描述，并明确标注优先级（P1/P2/P3）、独立可测试性与优先级理由。
- 国际化要求在所有涉及 UI 文案的规格中统一声明需支持 en、zh、zh-TW、ja、de-DE、es、fr、pt-PT 八种语言。
