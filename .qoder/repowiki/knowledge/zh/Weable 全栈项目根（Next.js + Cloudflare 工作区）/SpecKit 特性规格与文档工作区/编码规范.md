- 每个特性在 `specs/` 下以 `<三位数序号>-<kebab-case名称>` 的目录命名，序号自增或由 `--timestamp` 生成时间戳前缀。
- 特性目录固定包含 `spec.md`、`plan.md`、`research.md`、`data-model.md`、`quickstart.md`、`tasks.md` 与 `checklists/requirements.md`，API 契约放入 `contracts/` 子目录。
- `spec.md` 必须包含 User Scenarios（带 P1/P2/P3 优先级与 Independent Test 说明）、Requirements（FR-xxx 编号）、Success Criteria（SC-xxx 编号）与 Assumptions 四个章节。
- 所有模板文件位于 `.specify/templates/`，由脚本通过 `resolve_template` 解析并复制到新特性目录，禁止直接手写模板内容。
- Bug 修复采用 `.specify/bugs/<slug>/assessment.md` + `fix.md` 的双文件结构，由 bug triage 扩展的 `speckit.bug.*` 命令生成。
- 工作流与扩展通过 YAML schema 声明（`workflow.yml`、`extension.yml`），并在 `workflow-registry.json` / `extensions.yml` 中注册，保持配置即文档。
