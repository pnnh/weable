根目录作为 pnpm workspace 的入口，通过 `package.json` 集中声明 Next.js、Drizzle ORM、OpenNext Cloudflare 适配器、Tailwind CSS、Wrangler 等依赖，并由 `next.config.ts`、`open-next.config.ts`、`wrangler.jsonc`、`drizzle.config.ts`、`tsconfig.json` 五个配置文件共同定义构建与运行时契约：
- 构建链路：`pnpm build` → Next.js 编译 → OpenNext 将应用打包为 `.open-next/worker.js` → Wrangler 以 Cloudflare Worker 形式部署。
- 数据层：Drizzle 使用 SQLite dialect 生成迁移至 `./migrations`，本地开发用 better-sqlite3，生产通过 Wrangler 绑定 D1（DB）、R2（IMAGES_BUCKET、NEXT_INC_CACHE_R2_BUCKET）。
- 模块边界：frontend_app、api_endpoints、components、database_layer、shared_libs、locales、specs_and_docs 七个子模块通过 `@/*` 路径别名在 TypeScript 中互相引用，共享库提供 StorageAdapter、i18n、认证解析等跨模块能力。
- 国际化：locales 下的 JSON 文件被 shared_libs 中的 i18n 工具加载，供 components 与 frontend_app 渲染多语言界面。
- 文档驱动：specs_and_docs 通过 .specify/speckit 管理特性规格，与代码实现解耦但由同一工作区统一管理。
