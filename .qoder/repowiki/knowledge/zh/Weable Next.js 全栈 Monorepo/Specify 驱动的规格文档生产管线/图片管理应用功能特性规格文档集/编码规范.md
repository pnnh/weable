- 每个特性目录遵循统一的七件套文件结构：spec.md、data-model.md、plan.md、research.md、quickstart.md、tasks.md、checklists/requirements.md，并在 contracts/ 下按接口粒度拆分契约文档。
- spec.md 中用户故事必须包含优先级理由、独立可测试说明以及 Given/When/Then 格式的验收场景。
- 功能需求以 FR-XXX 编号列出，成功标准以 SC-XXX 编号列出，便于在 tasks.md 中逐条追踪覆盖。
- tasks.md 使用 Phase 分阶段推进，每个任务以 `[TNNN] [P?] [USx] 描述 文件路径` 格式记录，并通过 ASCII 依赖图显式表达任务间先后关系。
- API 契约文档统一以 Markdown 表格描述查询参数/表单字段、成功响应 JSON 示例与错误状态码映射，并明确标注版本与变更范围。
- i18n 键新增需在所有已支持语言文件（en、zh、zh-TW、ja、de-DE、es、fr、pt-PT）中同步补充，作为跨切面任务的固定检查点。
