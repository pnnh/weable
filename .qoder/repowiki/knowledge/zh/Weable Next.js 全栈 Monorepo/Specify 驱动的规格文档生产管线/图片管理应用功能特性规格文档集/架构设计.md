每个功能特性以独立子目录（如 `001-image-directory-tree/`）为单位组织，内部统一采用固定文件结构：`spec.md` 描述用户故事与验收场景、`data-model.md` 定义实体变更、`contracts/` 存放 API 契约（Markdown 表格形式的请求/响应规范）、`tasks.md` 将实现拆分为带依赖关系的 Phase/TID 任务并标注并行标记 `[P]`、`quickstart.md` 提供手动冒烟测试步骤、`plan.md`/`research.md`/`checklists/requirements.md` 分别承载计划、调研与需求核对清单。模块本身不产出代码，而是作为 Next.js App Router + Drizzle ORM 项目的上游设计输入，通过 `contracts/` 中的路由路径（如 `src/app/api/images/route.ts`）与 `tasks.md` 中精确到文件的 TID 任务建立双向追溯关系；编号前缀 `00x-` 体现功能的迭代顺序与分支命名约定。
