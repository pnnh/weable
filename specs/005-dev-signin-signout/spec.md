# Feature Specification: 开发环境模拟登录/退出页面

**Feature Branch**: `005-dev-signin-signout`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "实现/[lang]/account/signin和/[lang]/account/signout模拟页面，用于本地开发验证，仅在开发阶段可访问，生产环境走原有的认证逻辑（目前是通过cloudflare零信任来保护所有/[lang]/console开头的路由）。在signin页面提供文本框允许输入用户邮箱（必填）和用户名称（可选），确认后以输入的用户信息登录（邮箱相同用户或按邮箱新建用户），将旧用户退出。而signout页面显示当前登录用户信息，并提供退出登录按钮。退出登录后跳转至signin页面。若访问signout页面时用户未登录，提示当前未登录，并提供到signin页面的链接。取消当前代码中未登录回退到dev账号的逻辑，必须显式访问signin页面进行登录。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 开发环境通过模拟登录页显式登录 (Priority: P1)

开发者在本地开发环境中访问 `/{语言}/account/signin` 页面，输入用户邮箱（必填）和用户名称（可选），提交后即以该用户身份登录系统，可继续访问需要登录的控制台功能进行开发验证。若系统中已存在相同邮箱的用户，则直接以该已有用户身份登录；若不存在，则以输入的邮箱（及名称）自动创建新用户后登录。若提交前已有其他用户处于登录状态，旧用户的登录状态被清除（即"将旧用户退出"），登录身份切换为新输入的用户。

**Why this priority**: 这是整个功能的核心入口。取消自动回退 dev 账号后，显式登录页是开发环境获得用户身份的唯一途径，所有后续开发验证都依赖它。

**Independent Test**: 在开发环境启动应用后，访问登录页并输入一个全新邮箱提交，验证跳转后控制台功能以该新用户身份可用；再用另一邮箱重复提交，验证登录身份已切换。

**Acceptance Scenarios**:

1. **Given** 开发环境且当前未登录，**When** 开发者在登录页输入一个系统中不存在的邮箱并填写可选名称后确认，**Then** 系统以该邮箱创建新用户并以其身份登录。
2. **Given** 开发环境且系统中已存在邮箱为 A 的用户，**When** 开发者在登录页输入邮箱 A 后确认，**Then** 系统以该已有用户身份登录，不创建重复用户。
3. **Given** 开发环境且当前已以用户 X 登录，**When** 开发者在登录页以邮箱 B 确认登录，**Then** 用户 X 的登录状态被清除，当前登录身份变为用户 B。
4. **Given** 开发环境，**When** 开发者未填写邮箱直接确认登录，**Then** 系统拒绝提交并提示邮箱为必填项。

---

### User Story 2 - 开发环境查看当前身份并退出登录 (Priority: P2)

开发者访问 `/{语言}/account/signout` 页面，查看当前登录用户的信息（如名称、邮箱），并可点击退出登录按钮结束当前会话；退出后自动跳转回登录页。若访问该页面时并未登录任何用户，页面显示"当前未登录"的提示，并提供前往登录页的链接。

**Why this priority**: 退出与身份查看是登录闭环的补充，支撑多用户切换的开发验证场景，但依赖 P1 的登录能力先存在。

**Independent Test**: 登录后访问退出页，确认展示了当前用户的名称与邮箱；点击退出后确认跳转至登录页且控制台功能不再可用；在未登录状态下访问该页，确认显示未登录提示与登录页链接。

**Acceptance Scenarios**:

1. **Given** 开发环境且已以用户 X 登录，**When** 开发者访问退出页，**Then** 页面展示用户 X 的身份信息。
2. **Given** 开发环境且已登录，**When** 开发者在退出页点击退出登录按钮，**Then** 登录状态被清除并自动跳转至登录页。
3. **Given** 开发环境且未登录，**When** 开发者访问退出页，**Then** 页面显示"当前未登录"提示及前往登录页的链接。

---

### User Story 3 - 取消开发环境自动回退账号，强制显式登录 (Priority: P3)

移除现有行为：开发环境下未携带任何身份信息时自动以固定 dev 账号登录。变更后，开发环境未登录时访问需要登录的功能将被拒绝（与生产环境未授权访问的行为一致），开发者必须先通过登录页显式登录才能使用控制台功能。

**Why this priority**: 这是让模拟登录成为开发环境唯一身份来源的配套变更，保证开发验证行为与生产一致，但其价值建立在 P1 已可用的前提下。

**Independent Test**: 在未登录状态（清除本地登录标记后）访问控制台功能，验证被拒绝且不再自动获得 dev 账号身份；随后通过登录页登录后再次访问，验证恢复正常。

**Acceptance Scenarios**:

1. **Given** 开发环境且未登录，**When** 开发者访问任何需要登录的控制台页面或接口，**Then** 系统不再自动赋予 dev 账号身份，访问被拒绝。
2. **Given** 开发环境，**When** 开发者通过登录页完成登录，**Then** 需要登录的功能恢复可用，身份为登录页指定的用户。

---

### Edge Cases

- 开发者输入的邮箱格式明显无效（如不含 "@"）时如何处理？（按常规邮箱格式校验拒绝并提示）
- 输入的邮箱与已有用户相同、但同时填写了与该用户现存名称不同的名称时如何处理？（以邮箱匹配已有用户登录，不修改已有用户的既有资料；名称仅在新建用户时生效）
- 已登录用户访问登录页时的表现？（允许访问并正常提交，提交后切换为新身份；页面不阻断）
- 退出登录后再次访问退出页？（显示"当前未登录"提示与登录页链接）
- 多语言前缀下行为是否一致？（所有受支持语言前缀下的登录/退出页行为一致）
- 生产环境访问登录/退出页？（页面不可用，返回与访问不存在页面一致的结果，不暴露任何模拟登录能力）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在 `/{语言}/account/signin` 提供模拟登录页，包含邮箱输入框（必填）与用户名称输入框（可选）。
- **FR-002**: 登录页提交时 MUST 校验邮箱非空且为有效邮箱格式；校验不通过时 MUST 在页面提示错误且不执行登录。
- **FR-003**: 提交合法邮箱后，系统 MUST 查找与该邮箱匹配的现有用户；若存在，MUST 以该用户身份完成登录。
- **FR-004**: 若不存在与邮箱匹配的现有用户，系统 MUST 以该邮箱及所填名称创建新用户（名称未填写时使用合理默认值），并以其身份完成登录。
- **FR-005**: 登录成功 MUST 清除先前用户的登录状态，使当前会话仅持有新登录用户的身份。
- **FR-006**: 登录成功后 MUST 将开发者引导至控制台入口页面。
- **FR-007**: 系统 MUST 在 `/{语言}/account/signout` 提供退出页；当存在已登录用户时，页面 MUST 展示当前登录用户的名称与邮箱。
- **FR-008**: 退出页 MUST 提供退出登录操作；执行后 MUST 清除当前登录状态并跳转至登录页。
- **FR-009**: 未登录用户访问退出页时，页面 MUST 显示"当前未登录"提示，并提供前往登录页的链接。
- **FR-010**: 系统 MUST 移除开发环境下未登录时自动回退到固定 dev 账号的行为；未登录访问需要身份的功能时 MUST 被拒绝，与未授权访问的既有处理方式一致。
- **FR-011**: 登录页与退出页 MUST 仅在开发环境可访问；在生产环境访问这两个页面时 MUST 不可用（返回与不存在页面一致的结果），生产环境的用户身份 MUST 继续由既有外部零信任认证机制提供，不受本功能影响。
- **FR-012**: 登录与退出操作 MUST 在所有受支持的语言前缀下行为一致。

### Key Entities

- **用户（User）**: 系统中的账号实体，具有唯一邮箱、名称等属性；邮箱是匹配与创建用户的唯一依据，一个邮箱至多对应一个用户。
- **登录会话（Session）**: 当前操作者所持身份的临时凭证，同一时刻仅对应一个用户；登录切换与退出操作均作用于该会话。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 开发者在开发环境从打开登录页到以目标用户身份进入控制台，全程不超过 30 秒。
- **SC-002**: 以全新邮箱登录与以已有邮箱登录均一次提交即成功（100% 通过验收场景 1、2）。
- **SC-003**: 取消自动回退后，未登录访问受保护功能的拒绝率为 100%，不再出现任何自动赋予的默认身份。
- **SC-004**: 生产环境访问模拟登录/退出页的可用率为 0%（完全不可访问），且生产环境既有认证流程无任何回归。
- **SC-005**: 登录切换（旧用户退出、新用户登录）在单次提交内完成，无需开发者手动清理任何旧状态。

## Assumptions

- 本功能的页面与提示仅面向开发团队的本地开发验证使用，不面向最终用户，因此页面文案无需覆盖全部受支持语言的完整翻译，页面功能行为在各语言前缀下保持一致即可。
- 登录成功后默认跳转至控制台入口页面（`/{语言}/console`）。
- 以已存在邮箱登录时，输入框中填写的名称不会覆盖已有用户的既有资料；名称仅用于新建用户；新建用户未填名称时以邮箱作为默认名称。
- 模拟登录不引入密码或任何凭证校验（仅限开发环境，生产环境该页面完全不可达）。
- 生产环境继续由现有外部零信任认证网关保护 `/{语言}/console` 开头的所有路由，本功能不改变该机制。
- 退出登录仅清除本地登录状态，不删除或修改该用户在系统中的任何数据。
