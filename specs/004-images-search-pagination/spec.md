# Feature Specification: 控制台图片列表关键词搜索与分页

**Feature Branch**: `004-images-search-pagination`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "为/en/console/images页面增加简单的关键词搜索（搜索框和设置频道按钮放同一行）和传统分页功能（上一页下一页和页码），每页20条数据。注意在切换页面时如果当前有搜索条件注意保留搜索条件（可以使用GET请求通过URL传递查询参数）。实现搜索功能时要使用参数化查询避免产生SQL注入等安全问题。分页只处理当前parent_id的直接下级（包括图片文件和目录），不考虑手动点击目录左侧三角箭头展开下级的情况。并在列表中显示关联的频道名称（没有关联频道时显示空）、文件大小（KB或者MB）、修改时间字段。同时当批量设置频道和发布状态之后，刷新一下列表状态。注意最好不要整个页面刷新，因为那会导致当前属性列表页的已经展开和选中状态被重置。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按关键词查找当前目录下的条目 (Priority: P1)

用户在某个目录下积累了大量图片与子目录后，希望快速定位名称中包含特定关键词的条目，而不必逐行浏览。用户在列表上方的搜索框中输入关键词，列表立即只显示当前目录下名称匹配的直接条目（图片文件与目录）；清空关键词后恢复完整列表。

**Why this priority**: 查找是列表页最高频的诉求之一，目录条目越多搜索价值越大；且搜索条件需与分页、目录导航协同，是后续故事的基础。

**Independent Test**: 进入包含多个条目的目录 → 输入关键词 → 验证仅显示名称匹配的直接条目 → 清空关键词 → 验证列表恢复完整。

**Acceptance Scenarios**:

1. **Given** 当前目录下存在名称包含"logo"的图片与子目录若干, **When** 用户在搜索框输入"logo"并触发搜索, **Then** 列表仅显示当前目录下名称包含"logo"的图片与目录，且分页信息随之更新
2. **Given** 用户已输入搜索条件, **When** 用户清空搜索框并触发搜索, **Then** 列表恢复显示当前目录的全部直接条目，回到第 1 页
3. **Given** 搜索关键词在当前目录下无任何匹配, **When** 搜索生效, **Then** 列表展示清晰的"无结果"提示，不显示误导性内容
4. **Given** 用户在根目录输入关键词, **When** 搜索生效, **Then** 仅匹配根目录的直接条目，不匹配任何子目录内部的条目

---

### User Story 2 - 分页浏览当前目录条目 (Priority: P2)

当某个目录下的直接条目数量较多时，用户希望以每页 20 条的方式分页浏览，通过"上一页 / 下一页"按钮与页码快速定位。切换页码时，已输入的搜索条件保持不变。

**Why this priority**: 分页控制单页数据量、提升浏览性能与可读性；与搜索正交且可独立交付，但单独价值略低于搜索。

**Independent Test**: 进入包含超过 20 个直接条目的目录 → 验证仅显示 20 条且出现分页控件 → 点击"下一页" → 验证显示后续条目；输入搜索条件后翻页 → 验证搜索条件保留。

**Acceptance Scenarios**:

1. **Given** 当前目录有 45 个直接条目且无搜索条件, **When** 用户打开该目录, **Then** 列表显示前 20 条，分页控件显示共 3 页且当前为第 1 页，"上一页"不可用
2. **Given** 用户位于第 1 页, **When** 用户点击"下一页"或页码"3", **Then** 列表显示对应页的条目，当前页码高亮
3. **Given** 用户在搜索条件下位于第 2 页, **When** 用户继续翻页, **Then** 搜索条件全程保留，翻页结果始终限定在该搜索条件之内
4. **Given** 用户位于最后一页, **When** 用户查看分页控件, **Then** "下一页"不可用
5. **Given** 用户通过面包屑或点击目录进入另一个目录, **When** 新目录加载完成, **Then** 搜索条件与页码重置（新目录从第 1 页、无搜索条件开始）

---

### User Story 3 - 列表中查看频道归属、文件大小与修改时间 (Priority: P3)

用户在浏览列表时，希望直接看到每个图片的关联频道名称、文件大小与最近修改时间，无需逐个进入详情页即可判断素材状态。

**Why this priority**: 属于信息密度增强，提升管理效率但不阻塞核心浏览与查找路径。

**Independent Test**: 打开任一含图片的目录 → 验证图片行展示频道名称（未关联频道时为空）、文件大小（KB 或 MB）与修改时间；目录行相应列展示空值。

**Acceptance Scenarios**:

1. **Given** 某图片已关联频道"旅行", **When** 用户查看该行, **Then** 频道列显示"旅行"
2. **Given** 某图片未关联任何频道, **When** 用户查看该行, **Then** 频道列显示为空，不显示占位噪声
3. **Given** 某图片大小为 512000 字节与另一图片为 2.5 MB 级别, **When** 用户查看文件大小列, **Then** 分别以 KB、MB 为单位呈现人类可读的数值
4. **Given** 用户对某图片执行过更新操作, **When** 用户查看该行修改时间, **Then** 显示最新的修改时间

---

### User Story 4 - 批量操作后列表就地刷新且保留交互状态 (Priority: P4)

用户执行批量设置发布状态或批量设置频道并确认后，希望列表中的状态展示立即更新，同时当前已经展开的目录、已经勾选的图片不被重置——即不发生整页刷新导致的状态丢失。

**Why this priority**: 是既有批量功能（003）的体验闭环，依赖 P1–P3 的列表形态，属于增强型诉求。

**Independent Test**: 展开一个子目录并勾选若干图片 → 执行批量设置频道并确认 → 验证列表中的频道归属即时更新，且展开状态与（清空前的）勾选上下文无整页闪烁重置。

**Acceptance Scenarios**:

1. **Given** 用户已勾选若干图片并展开某子目录, **When** 用户完成批量设置频道并确认, **Then** 列表中受影响图片的频道归属即时更新，页面不发生整页刷新，已展开的目录保持展开
2. **Given** 用户完成批量设置发布状态, **When** 刷新完成, **Then** 受影响图片的发布状态展示即时更新，选择集按既有约定被清空
3. **Given** 批量操作失败, **When** 系统反馈错误, **Then** 展示友好错误提示，列表数据与交互状态保持操作前原样

---

### Edge Cases

- 搜索关键词包含特殊字符（引号、百分号、注入试探文本等）？——按普通文本匹配处理，不产生错误或越权数据访问，不泄露内部信息
- 页码参数非法（非数字、0、负数、超出总页数）？——按可理解的方式回退（如非法值按第 1 页处理，超出范围展示空结果或回退到有效页），不报错崩溃
- 当前目录直接条目不足 20 条？——不显示多余的页码，分页控件可隐藏或仅显示 1 页
- 搜索生效时目录行的展开子行如何呈现？——搜索与分页仅作用于当前目录的直接条目；已展开目录的子行展示不受搜索过滤与分页切割的影响（维持既有展开行为）
- 翻页或搜索期间数据发生变化（他人/他页删除条目）？——以当次查询结果为准，不产生错误页
- 目录行的频道名称、文件大小列？——目录不具备频道归属与文件大小语义，相应列显示为空
- 搜索与分页同时存在时进入某子目录？——进入新目录视为新的浏览上下文，搜索条件与页码重置

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 图片列表页（所有语言变体）的工具栏 MUST 提供关键词搜索框，且与"设置频道"按钮位于同一行
- **FR-002**: 搜索 MUST 按关键词对条目标题进行不区分大小写的模糊匹配，且匹配范围 MUST 限定为当前目录的直接条目（图片文件与目录）
- **FR-003**: 触发新的搜索 MUST 将列表重置为第 1 页；清空关键词 MUST 恢复显示当前目录的全部直接条目
- **FR-004**: 用户进入另一个目录（含经面包屑返回）时，搜索条件与页码 MUST 重置为初始状态（无关键词、第 1 页）
- **FR-005**: 列表 MUST 提供传统分页控件：上一页、下一页按钮与页码；每页固定显示 20 条当前目录的直接条目
- **FR-006**: 位于第 1 页时"上一页" MUST 不可用；位于最后一页时"下一页" MUST 不可用；当前页码 MUST 有明确的高亮标识
- **FR-007**: 分页与搜索仅处理当前目录（parent_id）的直接条目（图片文件与目录）；MUST NOT 将未展开目录内部的条目纳入分页或搜索结果
- **FR-008**: 搜索条件与页码 MUST 体现在页面地址（URL 查询参数）中：翻页全程保留搜索条件，且带条件的地址可直接访问或分享并还原相同视图
- **FR-009**: 非法的页码或搜索参数 MUST 被安全回退（如回到第 1 页或按空关键词处理），MUST NOT 导致页面错误
- **FR-010**: 搜索条件的处理 MUST 将用户输入作为参数对待，MUST NOT 将输入内容直接拼入查询语句；任何特殊字符或注入试探输入 MUST 仅被作为普通文本匹配，不得执行非预期的数据操作
- **FR-011**: 列表 MUST 显示关联频道名称列；图片未关联频道时该列 MUST 显示为空；目录行该列 MUST 显示为空
- **FR-012**: 列表 MUST 显示文件大小列，以 KB 或 MB 呈现人类可读的数值；目录行该列 MUST 显示为空
- **FR-013**: 列表 MUST 显示修改时间列，且反映条目最近一次更新的时间
- **FR-014**: 批量设置发布状态或批量设置频道成功确认后，列表数据 MUST 就地刷新（不发生整页刷新），且刷新 MUST NOT 重置已展开目录的展开状态
- **FR-015**: 本功能涉及的全部界面文案 MUST 支持项目现有的多语言体系（en、zh、zh-TW、ja、de-DE、es、fr、pt-PT）
- **FR-016**: 本功能的列表数据接口 MUST 遵循既有控制台接口约定：位于控制台接口前缀之下、执行前校验登录，未登录请求统一返回 401 状态码 + JSON 错误体；查询范围 MUST 限定为当前用户自有数据

### Key Entities

- **条目（图片/目录）**: 列表中的行实体；关键属性：标题、类型（图片或目录）、所属上级、关联频道（可为空）、文件大小、修改时间、发布状态。搜索、分页与新增列的承载对象
- **视图状态（View State）**: 一次列表浏览的上下文，由当前目录、搜索关键词、页码构成；可完整通过页面地址表达与还原，进入新目录时重置
- **频道（Channel）**: 用户创建的内容组织单元；关键属性：名称。列表中频道名称列的数据来源

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在 1000 条以内规模的目录中执行一次搜索或翻页，结果在 1 秒内可见
- **SC-002**: 带搜索条件的翻页操作中，搜索条件保留率达 100%（任何一次翻页后的结果均限定在该搜索条件内）
- **SC-003**: 批量操作确认后就地刷新在 2 秒内可见，且已展开目录的展开状态保持率 100%，无整页刷新闪烁
- **SC-004**: 特殊字符与注入试探类输入 100% 按普通文本处理，不产生错误响应、越权数据或内部信息泄露
- **SC-005**: 用户经分享/复制的带搜索条件与页码的地址访问，100% 还原出相同的列表视图

## Assumptions

- 关键词匹配字段为条目标题，采用不区分大小写的包含（模糊）匹配；不提供多字段、多关键词组合搜索
- 搜索与分页的作用范围均为当前目录的直接条目（图片文件与目录）；不跨目录、不递归搜索
- 用户通过面包屑或点击目录进入新的浏览上下文时，搜索条件与页码重置为初始状态
- 已展开目录的子行展示维持既有行为，不受搜索过滤与分页切割影响；分页计算不包含展开的子行
- 文件大小展示规则：不足 1 MB 以 KB 呈现，否则以 MB 呈现，保留合理精度；目录无文件大小与频道归属，相应列显示为空
- 列表排序维持既有规则（目录优先，其余按修改时间倒序），分页在既定排序上稳定切片
- 页码数量较多时分页控件仅展示有限页码窗口（含首尾页与当前页邻域），不展开全部页码
- 复用现有登录与鉴权体系及控制台接口前缀约定；列表数据仅返回当前用户自有条目
- 批量操作后的刷新以当前视图数据就地更新为准，沿用既有批量操作的失败提示与防重复提交行为
