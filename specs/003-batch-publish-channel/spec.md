# Feature Specification: 图片批量设置发布状态与频道

**Feature Branch**: `003-batch-publish-channel`

**Created**: 2026-08-06

**Status**: Draft

**Input**: User description: "在当前项目/en/console/images页面每个列表项最左侧和表头最左侧增加一个复选框，支持选择单个或多个图片文件。然后在顶部工具栏中增加设置发布状态按钮，点击后弹窗二次确认后将选中图片文件状态设置为已发布或未发布状态（修改images表is_published字段）。同时在工具栏中增加设置频道按钮，点击后弹窗二次确认允许用户选择频道（或者空），以下拉框形式呈现频道列表。当确认后，将选中图片的文件修改为指定值（修改images表channel_id字段）。"

## Clarifications

### Session 2026-08-06

- Q: 除新增的批量接口外，现有被 `[lang]/console` 页面调用的后端 API 中，哪些需要迁移到 `/[lang]/console/api` 前缀下？ → A: 控制台调用的所有 API 全部迁移；同时为公开页面创建独立 API（可以从原 API 拷贝逻辑）
- Q: 迁移完成后，原 `/api/*` 路径下的旧接口应如何处置？ → A: 直接删除全部原控制台接口路由，公开接口另建独立路径
- Q: 未登录请求访问 `/[lang]/console/api` 前缀接口时，系统应返回什么响应？ → A: 统一返回 401 状态码 + JSON 错误体

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 批量设置图片发布状态 (Priority: P1)

用户上传了大量图片到控制台后，需要一次性将其中若干张图片设置为"已发布"（或撤回为"未发布"）。用户在 `/en/console/images` 列表中勾选目标图片，点击工具栏的"设置发布状态"按钮，在弹窗中选择目标状态并确认，所选图片的发布状态立即更新并在列表中反映出来。

**Why this priority**: 发布/未发布是图片对外可见性的核心开关。当前用户只能逐个进入图片详情页修改状态，批量操作直接消除重复劳动，是本功能最高价值的部分。

**Independent Test**: 仅实现"复选框选择 + 批量设置发布状态"即可独立交付：勾选若干图片 → 点击按钮 → 确认 → 验证所选图片状态徽章全部变为目标状态。

**Acceptance Scenarios**:

1. **Given** 列表中存在多张图片且均未勾选, **When** 用户勾选其中 3 张并点击"设置发布状态"按钮, **Then** 弹窗出现，允许选择"已发布"或"未发布"，未确认前数据不发生变化
2. **Given** 弹窗中已选择"已发布", **When** 用户点击确认, **Then** 3 张图片的发布状态全部变为"已发布"，列表状态徽章即时更新，选中状态被清空
3. **Given** 弹窗已打开, **When** 用户点击取消或关闭弹窗, **Then** 不发生任何数据变更，勾选保持原样
4. **Given** 用户未勾选任何图片, **When** 用户查看工具栏, **Then** "设置发布状态"按钮处于不可用（禁用）状态

---

### User Story 2 - 批量设置图片所属频道 (Priority: P2)

用户整理素材时，希望把一组图片统一归入某个频道（或移出频道）。用户勾选目标图片，点击工具栏的"设置频道"按钮，弹窗中以下拉框展示当前用户的全部频道及"无频道（空）"选项，选择后确认，所选图片的所属频道立即更新。

**Why this priority**: 频道归属是图片组织与分发的次要维度，依赖 P1 的选择交互基础；独立价值略低于发布状态，但仍显著优于逐个修改。

**Independent Test**: 勾选若干图片 → 点击"设置频道" → 在下拉框选择某频道并确认 → 验证所选图片的频道归属更新为所选频道；再选择"空"确认 → 验证频道归属被清除。

**Acceptance Scenarios**:

1. **Given** 用户已勾选 2 张图片且用户名下存在至少一个频道, **When** 用户点击"设置频道"按钮, **Then** 弹窗出现，下拉框列出该用户的全部频道以及"空"选项
2. **Given** 弹窗中已选择某频道, **When** 用户点击确认, **Then** 2 张图片的所属频道更新为该频道，选中状态被清空
3. **Given** 弹窗中已选择"空"选项, **When** 用户点击确认, **Then** 所选图片的所属频道被清除（不再归属任何频道）
4. **Given** 用户名下没有任何频道, **When** 用户打开"设置频道"弹窗, **Then** 下拉框仅包含"空"选项，用户仍可确认后清除所选图片的频道归属

---

### User Story 3 - 通过表头复选框快速全选当前视图 (Priority: P3)

用户在进入某个目录后，希望快速选中当前视图中所有图片文件，而不必逐个勾选。用户点击表头最左侧的复选框，即可全选/取消全选当前可见的所有图片。

**Why this priority**: 是选择交互的效率增强，依赖 P1 的单选能力，价值明确但非独立可交付的核心路径。

**Independent Test**: 进入包含多张图片的目录 → 点击表头复选框 → 验证所有可见图片行被勾选且目录行不受影响；再次点击 → 验证全部取消勾选。

**Acceptance Scenarios**:

1. **Given** 当前视图包含若干图片与目录, **When** 用户点击表头复选框, **Then** 当前视图中所有图片文件行被勾选，目录行不参与选择
2. **Given** 当前视图所有图片已被表头复选框全选, **When** 用户手动取消其中 1 张的勾选, **Then** 表头复选框变为未全选状态（如半选态）
3. **Given** 用户在某目录内已勾选图片, **When** 用户切换到其他目录或根目录, **Then** 选择状态被清空

---

### Edge Cases

- 目录行是否可被勾选？——目录不具备发布状态与频道归属语义，目录行不显示复选框，不参与选择与批量操作
- 展开目录后，其子行中的图片是否可被勾选？——可以，选择范围为当前视图中所有可见的图片行（含已展开的子行），不递归选择未展开目录内的图片
- 用户未选择任何图片时点击批量按钮？——按钮处于禁用状态，无法触发操作
- 批量操作执行过程中用户重复点击确认？——确认按钮在提交期间应防止重复提交
- 批量操作部分失败（例如某图片已被删除）？——向用户展示友好的失败提示，并提示刷新页面；不展示技术错误细节
- 用户勾选图片后未做任何操作直接离开页面？——无副作用，选择不产生任何数据变更

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `/en/console/images` 页面（所有语言变体）的表格表头最左侧 MUST 提供一个复选框；每个图片文件行最左侧 MUST 提供一个复选框；目录行 MUST NOT 提供复选框
- **FR-002**: 表头复选框 MUST 支持全选/取消全选当前视图中所有可见的图片行（含已展开目录的子行）；当仅部分图片被选中时，表头复选框 MUST 呈现半选状态
- **FR-003**: 用户 MUST 能勾选单个或多个图片文件；选择状态仅属于客户端交互状态，不产生持久化
- **FR-004**: 页面工具栏 MUST 提供"设置发布状态"按钮；当未勾选任何图片时该按钮 MUST 处于禁用状态
- **FR-005**: 点击"设置发布状态"按钮 MUST 弹出二次确认弹窗，弹窗内提供"已发布"与"未发布"两个互斥选项；用户确认前 MUST NOT 发生任何数据变更
- **FR-006**: 用户确认发布状态后，系统 MUST 将所有选中图片的发布状态更新为所选值，且仅更新当前用户拥有的图片
- **FR-007**: 页面工具栏 MUST 提供"设置频道"按钮；当未勾选任何图片时该按钮 MUST 处于禁用状态
- **FR-008**: 点击"设置频道"按钮 MUST 弹出二次确认弹窗，弹窗内 MUST 以下拉框形式列出当前用户的全部频道，并额外提供"空"（不归属任何频道）选项
- **FR-009**: 用户确认频道选择后，系统 MUST 将所有选中图片的所属频道更新为所选值；选择"空"时 MUST 清除所选图片的频道归属；且仅更新当前用户拥有的图片
- **FR-010**: 批量操作成功完成后，系统 MUST 清空当前选择状态，并使列表中的状态展示（发布状态徽章等）反映最新数据
- **FR-011**: 批量操作执行期间 MUST 防止重复提交（确认按钮进入提交中状态直至操作结束）
- **FR-012**: 批量操作失败时，系统 MUST 向用户展示可理解的友好错误提示，且 MUST NOT 泄露内部技术细节
- **FR-013**: 本功能涉及的全部界面文案 MUST 支持项目现有的多语言体系（en、zh、zh-TW、ja、de-DE、es、fr、pt-PT）
- **FR-014**: 控制台页面调用的全部后端接口（含本功能新增的批量接口）MUST 位于 `/[lang]/console/api` 前缀之下，且 MUST 在执行任何数据操作前校验用户已登录；未登录请求 MUST 被拒绝，并统一返回 401 状态码 + JSON 错误体
- **FR-015**: 现有被控制台页面调用的接口（图片列表查询、图片上传、目录创建、单图片更新/删除、频道删除、频道头像上传、用户头像上传、用户资料更新）MUST 迁移至 `/[lang]/console/api` 前缀，页面端调用路径 MUST 同步更新；迁移完成后原 `/api/*` 下的对应控制台接口路由 MUST 被删除，不得保留可绕过登录校验的旧路径
- **FR-016**: 公开页面所需的接口 MUST 由独立的公开接口提供（允许从原接口拷贝逻辑），MUST NOT 复用控制台前缀接口

### Key Entities

- **图片（Image）**: 用户上传的文件或目录条目；关键属性：标题、是否已发布（is_published）、所属频道（channel_id，可为空）、归属用户、更新时间。批量操作的目标实体
- **频道（Channel）**: 用户创建的内容组织单元；关键属性：名称、归属用户。批量设置频道的候选来源
- **选择集（Selection）**: 纯客户端交互状态；包含当前视图中被勾选的图片标识集合，不持久化

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户对 10 张图片执行批量发布操作（勾选 → 点击按钮 → 选择状态 → 确认）全程不超过 30 秒，相较逐个修改减少至少 70% 的操作步骤
- **SC-002**: 批量操作确认后，列表状态反馈在 2 秒内可见（发布状态徽章或频道归属更新）
- **SC-003**: 50 张图片的批量操作在 3 秒内完成
- **SC-004**: 批量操作的数据准确性达 100%：确认前零数据变更，确认后所有选中图片均变为目标值，未选中的图片不受影响
- **SC-005**: 未登录用户或尝试修改他人图片的请求被 100% 拒绝，不产生越权变更

## Assumptions

- 复选框只出现在图片文件行；目录不具备发布状态与频道归属语义，不参与批量操作
- 选择范围为当前视图中可见的图片行（含已展开目录的子行）；不递归选择未展开目录内的图片，跨目录导航会清空选择
- "设置发布状态"弹窗中的目标状态由用户显式选择（"已发布"/"未发布"二选一），而非根据当前状态自动取反
- 复用现有登录与鉴权体系；批量操作仅允许作用于当前用户拥有的图片
- 批量操作的规模上限为单个视图中可见的图片数量，无需支持跨目录的海量选择
- 频道列表数据来自当前用户名下的频道；若用户尚无频道，下拉框仅提供"空"选项
- 操作成功后的反馈以列表状态即时刷新为准，不额外引入通知类组件
