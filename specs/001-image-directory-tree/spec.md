# 功能规格：图片目录管理与树形表格展示

**功能分支**：`001-image-directory-tree`

**创建日期**：2026-08-01

**状态**：草稿

**输入**：当前项目是一个部署在 Cloudflare Worker 上的图片管理应用。复用 images 表，mime_type 字段等于 directory 的视做是目录，images 表增加 parent_id 字段。在控制台图片管理页面新增"创建目录"功能，并将列表页改造为树形表格。

---

## 用户故事与测试场景 *(必填)*

### 用户故事 1 — 创建目录（优先级：P1）

管理员用户在图片管理控制台，点击"新建目录"按钮，弹出对话框输入目录名称（必填）和描述（选填），确认后在当前层级（根目录或当前父目录下）创建新目录。

**优先级理由**：目录结构是后续所有分类管理的基础，必须先能创建目录，才能向目录中上传图片。

**独立可测试**：可单独实现目录创建接口与弹框 UI，无需树形展示即可验证：新建目录后刷新页面，目录条目出现在列表中。

**验收场景**：

1. **Given** 用户已登录控制台图片管理页，**When** 点击"新建目录"按钮，**Then** 弹出包含名称输入框（必填）和描述输入框（选填）的对话框。
2. **Given** 对话框已打开，**When** 输入合法目录名并点击确认，**Then** 对话框关闭，新目录出现在当前层级列表中。
3. **Given** 对话框已打开且名称输入框为空，**When** 点击确认，**Then** 显示"名称不能为空"校验错误，表单不提交。
4. **Given** 当前层级已存在名为"设计稿"的目录，**When** 尝试在同一层级再次创建名为"设计稿"的目录，**Then** 显示"该层级已存在同名条目"错误，保存被阻止。
5. **Given** 当前层级已存在名为"banner.jpg"的图片，**When** 尝试在同一层级创建名为"banner.jpg"的目录，**Then** 显示"该层级已存在同名条目"错误，保存被阻止。

---

### 用户故事 2 — 树形表格展开/折叠（优先级：P2）

用户在图片管理列表页看到树形表格，目录条目最左侧有三角图标，点击可内联展开或折叠该目录的直接子条目（目录和图片）。

**优先级理由**：树形展开是树形浏览的核心交互，让用户无需跳转页面即可快速预览目录内容。

**独立可测试**：可在已有目录数据的前提下，单独测试展开/折叠交互——点击三角后当前行下方出现子条目，再次点击后子条目消失。

**验收场景**：

1. **Given** 列表中存在含子条目的目录，**When** 用户点击该目录行最左侧三角图标，**Then** 目录行下方内联展示直接子条目，三角图标方向变为朝下。
2. **Given** 目录已展开，**When** 用户再次点击三角图标，**Then** 子条目折叠隐藏，三角图标恢复朝右。
3. **Given** 空目录（无子条目），**When** 用户查看该目录行，**Then** 最左侧不显示三角图标或显示为禁用状态，点击无效果。
4. **Given** 已展开的目录中包含子目录，**When** 用户点击子目录的三角图标，**Then** 子目录的子条目进一步内联展开（递归支持多层）。

---

### 用户故事 3 — 点击目录条目进入子级列表（优先级：P2）

用户点击目录条目（非三角图标区域）后，页面导航至该目录的子级列表页，URL 携带 `parentId` 参数，页面仅显示该目录下的直接子条目，并显示面包屑导航。

**优先级理由**：页面级导航提供更清晰的"当前位置"感知，与展开/折叠互为补充，满足大规模内容管理场景。

**独立可测试**：在已有目录结构的前提下，点击目录条目，URL 变为 `/[lang]/console/images?parentId=xxx`，页面显示该目录的直接子条目。

**验收场景**：

1. **Given** 列表中存在目录条目，**When** 用户点击目录名称，**Then** 页面跳转至 `/[lang]/console/images?parentId={目录ID}`，仅显示该目录的直接子条目。
2. **Given** 用户处于子级列表页，**When** 查看页面顶部，**Then** 显示面包屑导航（如：根目录 > 设计稿），每级可点击返回。
3. **Given** 用户处于子级列表页，**When** 点击面包屑中的"根目录"，**Then** 返回根目录列表（无 `parentId` 参数）。
4. **Given** 用户在子级列表页，**When** 点击"新建目录"或"上传图片"，**Then** 新条目的 `parent_id` 自动设置为当前目录 ID。

---

### 用户故事 4 — 在指定目录下上传图片（优先级：P3）

用户在子级列表页（URL 含 `parentId`）上传图片时，图片的 `parent_id` 自动继承当前目录 ID。

**优先级理由**：这是目录功能完整闭环的最后一步，确保新上传的图片归属于正确的目录。

**独立可测试**：在子级列表页上传图片，验证数据库记录中 `parent_id` 等于当前目录 ID。

**验收场景**：

1. **Given** 用户在 `/[lang]/console/images?parentId=abc123` 页面，**When** 通过上传按钮上传图片，**Then** 上传成功后图片出现在当前子级列表中，`parent_id = abc123`。
2. **Given** 用户在根目录列表页（无 `parentId`），**When** 上传图片，**Then** 图片 `parent_id` 为空，出现在根目录列表中。

---

### 边界情况

- 目录名称包含特殊字符（如 `/`、`\`、`..`）时，系统应拒绝或对其进行安全处理。
- 同一父节点下（含根目录），目录名称与图片 `title` 均不允许重名（跨类型也需唯一）。
- 删除目录时，若目录下存在子条目，需明确处理策略（本期规格不包含目录删除功能，待后续迭代）。
- 用户访问不存在的 `parentId` 时，页面应返回 404 或重定向至根目录。
- 极深层级嵌套（如超过 10 层）的性能影响属于已知限制，本期不强制处理。

## 功能需求 *(必填)*

### 数据层需求

- **FR-001**：`images` 表 MUST 新增 `parent_id` 字段（可为空），指向同表 `id` 字段，用于表示父目录。`parent_id` 为空表示条目位于根目录。
- **FR-002**：`parent_id` 字段 MUST 在数据库层面通过外键约束引用 `images.id`，删除父目录时行为为 `SET NULL`（本期不实现目录删除，但约束需提前定义）。
- **FR-003**：系统 MUST 使用 `mime_type = 'directory'` 标识目录条目；目录条目的 `filename` 字段设为与 `title` 相同的值，`size` 字段设为 `0`，`width` / `height` 为 `NULL`。
- **FR-004**：创建目录时，系统 MUST 校验同一 `parent_id`（含 `NULL` 根目录）下不存在相同 `title` 的条目（目录或图片均计入），违反时返回错误并拒绝写入。

### 接口层需求

- **FR-005**：系统 MUST 提供创建目录的 API 接口，接受 `title`（必填）、`description`（选填）、`parentId`（选填，默认为根目录），返回新建目录的 `id`。
- **FR-006**：获取图片/目录列表的接口 MUST 支持 `parentId` 查询参数，过滤返回指定父目录下的直接子条目；`parentId` 缺省时返回根目录条目。
- **FR-007**：上传图片接口 MUST 接受 `parentId` 参数，并将其写入数据库 `parent_id` 字段。

### 界面层需求

- **FR-008**：图片管理控制台列表页 MUST 在"上传图片"按钮左侧新增"新建目录"按钮。
- **FR-009**：点击"新建目录"按钮 MUST 显示模态对话框，包含：名称输入框（必填，带校验提示）、描述文本框（选填）、确认与取消按钮。
- **FR-010**：提交对话框时，若名称已在当前层级存在，MUST 在对话框内显示明确的错误提示，不关闭对话框。
- **FR-011**：图片管理列表页 MUST 改造为树形表格，目录条目最左侧显示可点击的三角展开图标（▶/▼），图片条目该位置为空白缩进。
- **FR-012**：点击三角图标时，MUST 内联加载并展示该目录的直接子条目；再次点击折叠；展开/折叠状态仅维护在前端，刷新页面后重置为全部折叠。
- **FR-013**：点击目录条目名称时，MUST 导航至 `/[lang]/console/images?parentId={id}`，URL 参数驱动列表内容刷新。
- **FR-014**：子级列表页 MUST 显示面包屑导航，展示从根目录到当前目录的完整路径，每级可点击跳转。
- **FR-015**：当前页面的所有创建目录/上传图片操作 MUST 自动继承当前 `parentId`（URL 参数），确保新条目归属正确。

### 关键实体

- **目录（Directory）**：`images` 表中 `mime_type = 'directory'` 的条目，具有 `id`、`title`（目录名）、`description`（可选说明）、`parent_id`（父目录 ID，NULL 为根）、`user_id`、`created_at`、`updated_at`；`size = 0`，`width`/`height` 为 NULL。
- **图片（Image）**：`images` 表中 `mime_type` 为标准图片 MIME 类型的条目，新增 `parent_id` 字段，其余字段不变。
- **面包屑路径（Breadcrumb）**：从根目录到当前目录的有序列表，每项包含 `id` 和 `title`，用于 UI 导航。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：用户可在 3 次点击内（打开对话框 → 输入名称 → 确认）完成目录创建，目录立即出现在当前层级列表中，无需手动刷新。
- **SC-002**：同一父级下重名条目的创建请求 100% 被阻止，用户在对话框内看到清晰的错误提示。
- **SC-003**：树形表格展开操作响应时间不超过 1 秒（正常网络条件下）。
- **SC-004**：点击目录条目后页面切换到子级列表，URL 正确反映当前目录层级，支持浏览器前进/后退导航。
- **SC-005**：在子级列表页上传的图片 100% 正确归属于当前目录（`parent_id` 与 URL 中的 `parentId` 一致）。

## 假设

- 目录不支持跨目录移动（本期范围外）。
- 目录删除功能不在本期实现；删除逻辑留待后续迭代单独规划。
- 树形展开仅加载直接子条目（一层），不做预加载或懒加载优化（由浏览器端按需触发 API 请求）。
- `parent_id` 的循环引用（A 是 B 的父，B 是 A 的父）由应用层逻辑预防，本期不实现专项检测算法。
- 现有已上传图片的 `parent_id` 默认为 `NULL`（根目录），数据迁移仅添加字段，不做数据回填。
- 国际化（i18n）：新增 UI 文案需在所有已支持语言（`en`、`zh`、`zh-TW`、`ja`、`de-DE`、`es`、`fr`、`pt-PT`）中提供对应翻译键。
- 权限模型：本期不引入目录级访问控制，目录随 `user_id` 隔离，与图片保持一致。
